# 02 — System Boundary

## In scope
- cognitive state model
- event model
- context assembly
- executive decision contract
- packetization contract
- capability declaration
- organ/agent handoffs
- failure and retry semantics
- verification and evidence contracts
- observability
- estate integration map
- reference runtime interfaces

## Out of scope
- replacing LLM providers
- claiming autonomous authority beyond granted capabilities
- unrestricted shell execution
- credential storage in source control
- irreversible self-modification
- hidden background work without a scheduler/runtime
- anthropomorphic claims of consciousness as an engineering fact

## Boundary rule
Mind As OS defines the control plane semantics. Concrete execution belongs to estate organs and adapters.

## Trust zones
1. Operator input zone
2. Cognitive interpretation zone
3. Executive decision zone
4. Capability execution zone
5. Verification zone
6. Evidence/state-commit zone
7. Public-output zone

Cross-zone movement requires an explicit event and provenance record.

## Proof criterion
All code paths map to one or more in-scope boundaries and no reference implementation depends on an out-of-scope behavior.
